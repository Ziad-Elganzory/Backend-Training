## Answer in your own words:
- What problem does Observer Pattern solve?
    - it notifies multiple dependent observers automatically when the subject changes it's state without creating tightly coupled code between them
- What is the difference between Subject and Observer?
    - THe Subject is the source of data (events , state change) while the observer is the listener that listens to the state change as the subject notifies the observer
- Why is Observer useful for side effects?
    - because it achives the open closed principle since if you want to add a new logic , you just create a new listener without modifying the source of truth
- How are Laravel events/listeners related to Observer Pattern?
    - the event is the subject which is fired when the state changes and the listeners are the observers that acts when the state changes
- What is the difference between Observer and Strategy?
    -   Observer and strategy can be used together but the main concern of the observer is to notify the subscribers when the state changes , while the strategy chooses the desired behaviour based on cases
- Give three backend examples where Observer is useful.
    - UserRegisterd , OrderPlaced, PaymentSucceeded
- When should you avoid using Observer?
    - when the reaction is essential to the main operation and should happen inline, when the flow becomes hard to trace, when the order of operations is important,  if you use events to avoide service orchestration and when debugging becomes harder than the coupling removed
